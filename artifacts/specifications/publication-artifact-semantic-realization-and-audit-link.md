# Publication Artifact Semantic-Realization and Audit-Link Specification

Status: accepted for TASK-053
Version: 1.0.0
Profile: `briefforge-static-html-semantic-realization-profile:1.0.0`
Policy: `briefforge-semantic-conformance-assessment-policy:1.0.0`

## Boundary

Artifact existence and invocation evidence are prerequisites, not semantic proof. TASK-053 independently verifies persisted TASK-052 authority/evidence/bytes, independently derives an expected semantic inventory from governed authority, independently extracts an actual inventory from HTML structure, compares exact closure, and emits one conformance record only for a complete passing assessment.

## Profile scope

The accepted `1.0.0` profile is intentionally narrow: exactly one Plan-authorized `native` statement in proved `observation` encounter mode, bounded single-line plain-text semantic fields, no long-document navigation and no static fallback. It assesses only meaning carried by that exact authorized `MinimalHtmlRendererProjection`:

- package identity, title, purpose and non-scope;
- ordered statements, selected expression modes and encounter semantics;
- statement authority, governed references and obligations;
- reference owner/kind/locator/meaning/provenance;
- obligation category/requirement/authority/targets;
- validation and semantic fingerprints;
- meaning-bearing hierarchy/order and inert Unicode/HTML escaping;
- absence of unauthorized meaning-bearing content.

Renderer-owned presentation vocabulary is allowed only by exact structural roles and fixed literal/derived rules named by the profile. It cannot introduce factual claims, obligations, references or governed identities.

## Authorization

One immutable authorization binds exact identities/fingerprints for Release, lifecycle scope, Plan, capability, TASK-052 invocation authorization/evidence, artifact digest/length/name/media type, renderer implementation, profile, assessor implementation, authority/time, output record class, limits and exclusions. Reuse or drift blocks before assessment.

## Independent expectation

Expected requirements are reproduced from exact persisted semantic records, active Release/lifecycle and verified Plan mappings. Every stable requirement identity combines its governed source identity, role and field. Every applicable requirement receives one outcome: `conformant`, `nonconformant`, `not-applicable`, or blocking `indeterminate`.

## Strict actual extraction

The assessor parses detached verified UTF-8 HTML bytes without browser, JavaScript, renderer, network or database execution. It requires the exact supported element/attribute inventory, eight-region order, direct and nested hierarchy, and governed identities. It rejects malformed/ambiguous nesting, duplicate attributes or governed identities, comments in semantic regions, active/external content, hidden/inert substitution, href/text spoofing, undeclared semantic nodes, cross-region relocation and unsupported structure.

## Comparison and verdict

Approval is mechanically derived only when:

- all exact authority/artifact bindings verify;
- the profile applies;
- every expected requirement appears exactly once and is conformant;
- all actual meaning-bearing realizations close to an expected requirement or exact allowed presentation rule;
- audit links are complete, unique, correctly directed and fingerprint-consistent;
- no blocking/indeterminate finding exists.

Callers cannot override findings or manufacture approval. Failure returns complete findings and no usable conformance record.

## Evidence

A fingerprint-specific consumption record is exclusively created and directory-fsynced before assessment, so replay or concurrent reuse blocks before semantic extraction. A passing ten-record closure appends exactly one `SemanticArtifactConformanceRecord` with a required must-preserve extension binding authorization, policy/profile/assessor, exact upstream closure, expected/actual inventories, per-requirement outcomes, limitations and audit links. Canonical evidence, the admission commitment and their containing directory entries are durably committed and independently reloaded under the TASK-052 local-writer model.

## Non-authority

Conformance is not Manifest authority, distribution authority, successful publication, factual re-adjudication, visual/editorial/accessibility certification or browser behavior proof. Audit linkage is traceability, not semantic proof by itself. Historical evidence is never rewritten.
