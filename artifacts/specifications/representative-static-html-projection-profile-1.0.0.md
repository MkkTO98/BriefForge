## Authored table semantics

Exactly one Candidate exhibit of kind `fixed-static-table` contains 1–16 authored `case_bindings`. Each has stable ID, explicit contiguous integer order, `primary_ref` and `comparison_ref`. These are immutable Release semantics. The renderer never pairs, orders or names value roles itself.

Rows are ordered by admitted `order`, then primary, then comparison. Fixed columns:

1. case and slot;
2. exact value/state;
3. unit;
4. semantic type;
5. source.

The value cell has fixed child fields: value identity, exact state, coefficient and scale when admitted, reason when admitted, approximation qualifier when admitted, and content-authority reference. Optional fields are omitted only by explicit value-state/profile rules; empty cells and invented defaults are forbidden. No arbitrary columns, sorting, cells, spans, tables, markup, conversion or rounding.

## Independent conformance

The assessor independently reconstructs expected field/edge inventory from reverified Release/lifecycle/Plan/authorization, without calling renderer projection/formatting helpers. It independently parses exact artifact bytes.

Every outcome binds source identity, projection rule, role/field, planned/realized cardinality, parent/order, value/state/unit, qualification target, provenance closure, obligation fields/targets and duplication rule.

- `conforming`: complete exact equality and no unplanned item;
- `non-conforming`: parsed evidence proves semantic mismatch;
- `indeterminate`: evidence cannot be completely and safely reconstructed or parsed.

Only conforming produces an accepted record. Its BCRP semantic aggregate remains `approved` for TASK-054 compatibility while extension payload status is `conforming`. Non-conforming/indeterminate return findings and no record.
